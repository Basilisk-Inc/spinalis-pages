The trained models are ordinary builds on the platform: triage six epochs at LoRA rank 32, SQL up to fifteen epochs on the written pairs plus the ones the platform synthesised and checked by execution, the checkpoint chosen by execution accuracy on held-out questions — every other setting left at its default. 05How it works

One real run, screen by screen.

Real screens from one run: the retinal-photograph model above, built from a public archive on one desktop GPU. Patient images are blurred here.

  1. Ingestshape recognised · PII scan · leak check
  2. Synthesisepairs kept only if round-trip execution agrees
  3. TrainLoRA / QLoRA · seed · environment manifest

  5. Sign offhuman approval gates production
  6. ServeOpenAI-compatible · output guards

every stage writes to one append-only, hash-chained audit journal

  1. Drop in the material as it is.

    4,217 retinal photographs go in as an archive — no manifest, no script. The platform catalogues every file, recognises the folder-per-condition layout and offers the preparation that fits.

    Then it asks the one question that decides whether any later number can be trusted: which images come from the same source, so they never land on both sides of the evaluation.

  2. It finds the leak before the metric does.

    Before any training, a bundled image encoder compares every picture with every other. On the first split it flagged 49 near-identical pairs that the patient number in the file name had not grouped together — differently named copies of the same photograph.

    What the leak was worth. Accuracy on the first split, and on the corrected one:93.3%→91.7%The lower number is the one a regulator can rely on.

  3. Evaluated on patients it has never seen.

    Training and evaluation are one build on your GPU. The report leads with what a reviewer needs — accuracy, macro recall, precision, F1, ROC-AUC and the confusion matrix — so the classes the model confuses stay visible instead of being averaged away.

    • pinned seed, dataset hash, environment manifest

  4. Nothing reaches production without a named approver.

    The model is packaged as a solution and deployment stays blocked until a person with the right role approves it. The Annex IV technical file is generated from the build record; people write only what a machine cannot know — intended purpose, limitations, risks.

  5. Every artefact traces back to its inputs — and every action is journalled.

    Lineage is derived from what actually happened — which archive a dataset came from, what a build trained on, which solution packages it. Uploads, builds, approvals and deployments land in a hash-chained journal; one click verifies the chain.

What your security team will ask

It is air-gapped. How does it get updates?

Like your other offline software: a release archive comes in through your approved transfer process, you check its SHA-256, and the binary verifies its own integrity at every start. No auto-update, nothing phones home.

Code signing and a software bill of materials are being added to the release chain.

How do libraries and models get inside?

Python libraries arrive as runtime packages — every wheel pinned for your operating system — installed offline from Settings → Libraries. Open-weight base models are copied from approved media and registered by a scan. Nothing is downloaded at run time.

Does it work with our security controls and our encryption keys?

It runs inside them. Database, datasets, models and audit journal live in directories you choose, under your disk encryption and your keys — BitLocker, LUKS, FileVault, an encrypted SAN. SPINALIS holds no key to your data and has no remote access; the journal’s signing keys are generated on the installation itself.

Put it behind your TLS-terminating proxy and network segmentation. Native single sign-on and HSM-held keys are not built in yet.

What leaves the machine?

Nothing that carries customer data. The licence is a signed file checked offline against the machine it was issued for, and there is no telemetry. Roles separate who trains, who approves and who audits.

06No lock-in

Leaving is a supported path.

A proprietary platform should not mean proprietary models, formats or records. Everything SPINALIS produces is yours in a form other tools can read.

Your models are standard

Built on open-weight base models. Export the weights, a GGUF file, a Docker service or a Python package, and run them without SPINALIS.

Your applications don't depend on us

Deployed models answer an OpenAI-compatible API. Moving an application to another server behind that API is a change of base URL.

Your data stays in open formats

Datasets are JSONL, CSV and image folders on your own disks. Nothing is converted into a format only we can read.

Your evidence is exportable

The audit journal exports to CSV, technical documentation to Markdown and PDF, and lineage to JSON through the API.

A lapsed licence locks nothing

If a licence expires, the installation keeps running at the free Community limit of one GPU. Models, datasets and records stay exactly where they are.

Standard machine learning underneath

PyTorch, Hugging Face Transformers and PEFT adapters — the same open stack your own engineers would choose, with no copyleft components.

10Questions

What security, compliance and business teams ask first.

Will we lose quality by moving from a frontier API to a small model?

On well-defined tasks, not much: message triage 90.3% for a 1.5B model trained on the platform versus 84.9% for GPT-5.5; dental X-ray findings 80.7% versus 30.8%. On SQL the trained 7B model matched the reference queries exactly more often (14 against 9 of 39), while GPT-5.5 produced more equivalent answers (18 against 15). A frontier model stays broader; the full comparison.

Are we locked in to SPINALIS?

No. Models export in open formats, applications talk to an OpenAI-compatible API, data stays in JSONL, CSV and image folders, and the evidence exports to CSV, Markdown, PDF and JSON. A lapsed licence falls back to the free one-GPU Community limit and locks nothing. Details.

Does any of our data leave the network?

No. No outbound connection carries customer data and there is no telemetry: the licence is a signed file verified offline. Updates, libraries and models come in through your own transfer process. How.

Does using SPINALIS make us compliant with the AI Act?

No tool can. The intended purpose, the risk assessment and the conformity decision remain yours. SPINALIS enforces the controls — roles, sign-off, an append-only journal — and generates the evidence from what actually happened, so your people review a record instead of writing one.

What exactly is in the Annex IV file?

A Markdown and PDF document per solution, assembled from the build record: general description and intended purpose; development process and training configuration, including the environment for reproducibility; data and data governance for every dataset; accuracy and performance metrics; risk management; changes through the lifecycle from the audit journal; human oversight and sign-off; and the conformity context. Fields no machine can know are written by people in the product, and every edit is journalled.

What hardware do we need?

One machine with a GPU inside your perimeter. Every result on this page came from a single 16 GB desktop GPU, which also serves about 4,000 triage requests an hour — measured training times and serving rates. Installers exist for Windows, Linux and macOS on Apple Silicon.

Which models can we train?

Open-weight models across the range: language models for text, documents, search and SQL; vision models for classification, detection and segmentation; speech models for transcription; and models for tables and time series — from a curated catalogue you extend offline. Trained models are served through an OpenAI-compatible endpoint or exported.

Is SPINALIS open source?

No. It is proprietary software under an end-user licence governed by EU law, built on a permissive-only dependency stack with no copyleft components — which is what lets regulated procurement accept it. The Community tier is free for one governed system.
