01The problem

Not a training gap. Not an inference gap. An evidence gap.

Open-weight models now run on a single GPU, and can be customised on private data without a cluster. The tools that do it are excellent. None of them produce the record a regulated organisation is legally obliged to hold.

Under Regulation (EU) 2024/1689, an organisation that fine-tunes a model on its own data may itself become the provider of a high-risk AI system — and inherit the obligations of Chapter III.

Audit trails, lineage, reproducibility and enforced human sign-off are not features of a trainer. They are properties of a governed process. Today that documentation is written afterwards, by hand, about work that left no trace.

02Why now

December 2027

Binding obligations for the high-risk systems listed in Annex III of the EU AI Act apply from December 2027. Procurement in regulated organisations runs twelve to twenty-four months — the purchasing decisions are being made now.

The data cannot leave

Finance, insurance, defence and public administration are barred — by data-protection law, sectoral regulation, national security rules or internal classification — from sending proprietary or personal data to third-country cloud AI services.

A sovereign cloud is not the answer on its own

EU sovereign-cloud offerings keep data inside the Union and may satisfy part of the financial sector. They do not enter an air-gapped network, they do not meet an absolute no-egress policy, and they do not produce the evidence.

03How it works

One real run, screen by screen.

Every screen below is the product itself, captured on one desktop GPU while building a retinal-photograph triage model from a public research archive. Patient images are blurred on this page.

  1. Drop in the material as it is.

    An archive of 4,217 retinal photographs goes in without a manifest or a script. SPINALIS catalogues every file, recognises the folder-per-condition layout, and offers the preparation that fits.

    Then it asks the question that decides whether any later metric can be trusted: which images come from the same source, so they never end up on both sides of the evaluation.

    • recognised images in directories named after their class · 90% confident
    • group key read from the file name, no code

  2. It finds the leak before the metric does.

    Before any training, a bundled image encoder compares every picture with every other. On the first split it flagged 49 near-identical pairs that the patient number in the file name had not grouped together — differently named copies of the same photograph, free to land in training and in evaluation at once.

    One change to the grouping rule, one re-split: the held-out set now shares no patient or image number with training, and held-out images with a near-identical match in training fell from 24 to 4.

    What the leak was worth. Accuracy on the first split, and on the corrected one:93.3%→91.7%The lower number is the one a regulator can rely on.

  3. Evaluated on patients it has never seen.

    Training and evaluation run as one build on your GPU. The report leads with what a reviewer needs: accuracy, macro-averaged recall, precision and F1, ROC-AUC, and the full confusion matrix — so the classes the model confuses are visible, not averaged away.

    • 91.7% accuracy on 420 held-out images
    • 0.989 ROC-AUC · macro-F1 91.3%
    • pinned seed, dataset hash, environment manifest

  4. Nothing reaches production without a named approver.

    The model is packaged as a solution and deployment stays blocked until a person with the right role approves it. Separation of duties is enforced by the platform, not by a policy document.

    The Annex IV technical file is generated from the build record. People write only what a machine cannot know — intended purpose, known limitations, risks — and every edit is journalled.

  5. Every artefact traces back to its inputs.

    Lineage is derived from what actually happened: which archive a dataset was prepared from, which datasets a build trained and was evaluated on, which base model it fine-tuned, which solution packages it. Ask where a model came from and the answer is a graph, not an interview.

  6. Every action lands in a tamper-evident journal.

    Uploads, builds, evaluations, approvals, deployments and document edits are appended to a hash-chained journal with per-installation Ed25519 anchors. One click verifies the chain; an auditor exports it as CSV.

    • append-only no update, no delete
    • separate role auditors read, never write

Technical core

Execution-grounded verification

Model outputs are executed against a governed, versioned data snapshot and compared by result, not by textual similarity. Text metrics cannot tell correctness from resemblance; running the output settles it.

reference SELECT COUNT(*) FROM loans WHERE status = 'default'
different text SELECT COUNT(id) FROM loans WHERE status IN ('default') same result — correct
near-identical SELECT COUNT(*) FROM loans WHERE status = 'defaulted' different result — wrong

Illustrative; id is the primary key.

The same primitive is used three times: to measure model quality, to filter synthetic training data by round-trip execution, and to constrain what a deployed endpoint may return. One piece of audited infrastructure instead of three heuristics.

Technical core

Cryptographic provenance

Every action is written to an append-only, hash-chained audit journal with per-installation Ed25519 anchors: tampering is detectable, not merely prohibited.

Every build is pinned by random seed, dataset hash and environment manifest, so a result obtained today can be reconstructed and re-verified years later — the precondition for any conformity claim that survives scrutiny.

The dependency stack is permissive only (Apache-2.0, MIT, BSD). Copyleft components are excluded by policy — including faster training kernels, whose speed is forgone deliberately so the product stays procurable.

No outbound connection carries customer data. A single binary with an embedded web interface and a bundled Python runtime; installers for Windows, Linux and macOS (Apple Silicon); no cluster, no platform team.

Evidence that accumulates

The audit chain, lineage graph and revalidation history build up over years inside the customer's perimeter — and cannot be reconstructed by a successor tool.

Who else competes for this budget

Building it internally the primary competitor
A capable bank can assemble open-source training and serving tools in a fortnight. The governance layer — access control, enforced sign-off, tamper-evident audit, lineage, reproducible builds, generated technical files, scheduled revalidation — is several engineer-years, delivers no visible capability, and is the part that never gets built.
Open-source trainers and no-code studios e.g. Unsloth Studio
Excellent and free; training throughput is conceded, not contested. No audit trail, lineage or conformity artefacts, no accountable vendor — and the Unsloth Studio UI is licensed AGPL-3.0, a copyleft licence procurement in regulated sectors rejects.
AI governance and GRC platforms
Closest in purpose. They collect policies, questionnaires and attestations above the engineering process; their output is still an assertion typed by a person. SPINALIS sits inside the process and derives the artefacts from execution. The two are compatible.
Cloud fine-tuning services
Technically strong, and excluded wherever data may not leave. Hyperscaler sovereign-cloud offerings in the Union may satisfy part of financial services; air-gapped defence and government, absolute no-egress policies and the evidence layer itself remain out of their reach.
Local inference runtimes
They solve serving, not customisation or governance — and are complementary: SPINALIS exports to open weight formats they can serve.

10Questions

What security and compliance teams ask first.

Does any of our data leave the network?

No. No outbound connection carries customer data, and there is no telemetry: the licence is a signed file verified offline against the machine it was issued for. The encoders that analyse your datasets ship as part of the installation rather than being fetched at run time.

Does using SPINALIS make us compliant with the AI Act?

No tool can. The intended purpose, the risk assessment and the conformity decision remain yours. What SPINALIS does is enforce the controls — roles, sign-off, an append-only journal — and generate the evidence from what actually happened, so your people review a record instead of writing one.

What exactly is in the Annex IV file?

A Markdown and PDF document per solution, assembled from the build record: general description and intended purpose; development process and training configuration, including the training environment for reproducibility; data and data governance for every dataset used; accuracy and performance metrics; risk management; changes through the lifecycle from the audit journal; human oversight and sign-off; and the conformity context.

Fields no machine can know — intended purpose, known limitations, risks — are written by people in the product, and every edit is journalled.

How do we know the reported numbers are honest?

Evaluation runs on data held out from training, split by group so records from the same source stay on one side. Near-duplicates the grouping missed are detected before training. Reports show per-class results and the confusion matrix, not only an average. Builds pin their seed, dataset hash and environment, so anyone can re-run one and compare.

What hardware do we need?

One machine with a GPU inside your perimeter. Every demonstration on this page ran on a single 16 GB desktop GPU. Installers exist for Windows, Linux and macOS on Apple Silicon; no cluster and no platform team are required.

Which models can we customise?

Open-weight small language models for text tasks, vision transformers for image classification and detectors for finding objects in images, chosen from a curated catalogue. Trained models are served through an OpenAI-compatible endpoint or exported to open weight formats.

Is SPINALIS open source?

No. It is proprietary software under an end-user licence governed by EU law, built on a permissive-only dependency stack with no copyleft components — which is what lets regulated procurement accept it. The Community tier is free for one governed system.
